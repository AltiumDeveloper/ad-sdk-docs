# Writing an OutJob outputer

An *outputer* adds an output type to Output Job (`.OutJob`) files, next to the built-in ones such as the bill of
materials or Gerber files. An extension provides it with three parts:

- a **`.out` file** in the extension's folder that declares the output: its name, its category in the OutJob, and the
  class that creates it;
- a method **`InvokeOutputGenerator`** on that class, which Altium Designer calls to create the outputer;
- the **outputer class**, derived from `Altium.Edp.Classes.OutputGenerator` (in `Altium.SDK.dll`), which predicts the
  names of the files it writes and writes them.

Like the `.ins` and `.rcs` files, the `.out` file is read when Altium Designer starts.

## The .out file

The file is named after the extension (`MyExtension.out`) and sits next to its `.ins` file. This one declares a
project report in the Report category:

```text
[OutputGenerator]
Name                    = MyExtension Report
Module                  = MyExtension.dll
ServerName              = MyExtension
ClassName               = MyExtension.PluginFactory
Description             = MyExtension project report
DocumentKinds           = Project
DefaultFolderName       = MyExtension Report
CanGenerateFromProject  = True
CanGenerateFromDocument = False
CanGenerateNetlist      = False
CanGenerateReport       = False
CanGenerateOutputFiles  = True
CanGenerateMetaPages    = False
CanPreferencesForm      = False
CanPropertiesForm       = False

[Output1]
Name            = MyExtension Report
Caption         = MyExtension Report
Description     = Components and nets of the project, as text
Category        = Report
RequiresCompile = True
```

| Key | Meaning |
| --- | --- |
| `Module` | The assembly, in the extension's folder. It can be the extension's own assembly (the `EditorExePath` of the `.ins` file). |
| `ServerName` | The extension's server (the `EditorName` of the `.ins` file). |
| `ClassName` | The full name of the class that has `InvokeOutputGenerator`. It can be the extension's plugin factory. |
| `Name` (in `[OutputGenerator]`) | The outputer's name; the outputer passes the same name to the `OutputGenerator` constructor. |
| `[Output1]` `Name` | The output type. An OutJob refers to the output by this name (see [The output in the OutJob](#the-output-in-the-outjob)). |
| `Caption`, `Description` | The text of the output in the OutJob; an output added to an OutJob is named after the `Description`. |
| `Category` | The OutJob group the output appears in, for example `Report`, `Netlist` or `Export`. |

The other keys are copied from installed outputers. The installed outputers of Altium Designer have `.out` files of the same format, in its `System` folder and in the
folders of its extensions.

## Creating the outputer

Altium Designer creates the outputer by calling `InvokeOutputGenerator()` on the class that `ClassName` names, by
name. Declare that class with `ClassInterfaceType.AutoDispatch`, so that the method is reachable that way. The
extension's plugin factory can serve both purposes:

```csharp
using System.Runtime.InteropServices;
using DXP;

namespace MyExtension
{
    public interface IPluginFactory
    {
        object InvokePluginFactory(IClient client);
    }

    [ClassInterface(ClassInterfaceType.AutoDispatch)]
    public class PluginFactory : IPluginFactory
    {
        public object InvokePluginFactory(IClient client) => new PluginServerModule(client, "MyExtension");

        public object InvokeOutputGenerator() => new ReportGenerator();
    }
}
```

## The outputer class

`OutputGenerator` drives the generation; an outputer overrides a few of its protected members:

| Member | Purpose |
| --- | --- |
| `InternalSetOutputPath(string targetFolder)` | Receives the folder to write to. |
| `InternalPredictOutputFilenames(IStrings filenames)` | Adds the full path of each file the output writes. |
| `InternalRunGenerator()` | Writes the files. Returns `true` on success. |
| `InternalRunPropertiesForm()` | Configures the output; returning `true` accepts the configuration as it is. |

During generation, the `Project` property is the project, `DocumentPath` the data source selected in the OutJob, and
`TargetPrefix` and `ExplicitTargetFilename` the file naming set in the OutJob. Report each file with
`Notify_BeginGeneratingOutputFile` and `Notify_FinishGeneratingOutputFile`, and errors with `HandleOutputerError`.

```csharp
using System;
using System.IO;
using System.Runtime.InteropServices;
using Altium.Edp.Classes;
using DXP;

namespace MyExtension
{
    [ComVisible(true)]
    [ClassInterface(ClassInterfaceType.AutoDispatch)]
    public class ReportGenerator : OutputGenerator
    {
        private string _folder;

        public ReportGenerator() : base("MyExtension Report") { }   // = Name in MyExtension.out

        protected override void InternalSetOutputPath(string targetFolder) => _folder = targetFolder;

        protected override bool InternalRunPropertiesForm() => true;

        protected override void InternalPredictOutputFilenames(IStrings filenames)
        {
            var file = OutputFile();
            if (filenames != null && file != null)
                filenames.Add(file);
        }

        protected override bool InternalRunGenerator()
        {
            var file = OutputFile();
            if (file == null)
            {
                HandleOutputerError("MyExtension Report: there is no project.");
                return false;
            }

            Notify_BeginGeneratingOutputFile(file);
            try
            {
                Directory.CreateDirectory(Path.GetDirectoryName(file));
                File.WriteAllText(file, "Project: " + Path.GetFileName(Project.DM_ProjectFullPath()));
                return true;
            }
            catch (Exception ex)
            {
                HandleOutputerError("MyExtension Report failed: " + ex.Message);
                return false;
            }
            finally
            {
                Notify_FinishGeneratingOutputFile(file);
            }
        }

        private string OutputFile()
        {
            var projectPath = Project?.DM_ProjectFullPath();
            if (string.IsNullOrEmpty(projectPath))
                return null;
            var name = !string.IsNullOrWhiteSpace(ExplicitTargetFilename)
                ? ExplicitTargetFilename
                : (TargetPrefix ?? string.Empty) + Path.GetFileNameWithoutExtension(projectPath) + ".txt";
            var folder = string.IsNullOrWhiteSpace(_folder) ? Path.GetDirectoryName(projectPath) : _folder;
            return Path.Combine(folder, name);
        }
    }
}
```

## The output in the OutJob

In the OutJob, the output appears under its category (**Add New Report Output** for `Category = Report`). Link it to
an output container, for example **Folder Structure**, and generate the container's content. The OutJob file stores
the output in its `[OutputGroup1]` section by the `[Output1]` `Name` of the `.out` file:

```text
OutputType1=MyExtension Report
OutputName1=Components and nets of the project, as text
OutputDocumentPath1=
OutputEnabled1=1
OutputEnabled1_OutputMedium3=1
```

`OutputDocumentPathN` is the data source selected for the output, and `OutputEnabledN_OutputMediumM` links output
`N` to output container `M` (`OutputMediumM=Folder Structure` in the same section).

## Developing an outputer

The `.out` file and the assembly that contains the outputer class take effect only after a restart (see
[Development loop](./development-loop.mdx#what-needs-a-restart)). Keep the outputer class small and stable, and move
the code that writes the content into an assembly that the extension loads itself. A hot-reload setup then changes
the content of the next generated file without a restart: the outputer passes the project and the file name to a
command of the hot-reloaded implementation.
