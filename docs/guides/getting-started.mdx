# Getting started

An Altium Designer extension is a .NET class library that Altium Designer loads as a *server*. The server registers
*commands*; menus, toolbars and shortcuts invoke the commands, and each command works with the documents through the
SDK interfaces.

## Project setup

Create a C# class library and reference the SDK assemblies:

| Assembly | Contents |
| --- | --- |
| `Altium.SDK.Interfaces.dll` | The API: interfaces, enumerations and structures (this reference). |
| `Altium.SDK.dll` | Hosting classes ([`DXP.ServerModule`](../reference/dxp/ServerModule.md), [`DXP.CommandLauncher`](../reference/dxp/CommandLauncher.md)), entry points (`SCH.GlobalVars`, `PCB.GlobalVars`, `DXP.GlobalVars`), constants ([`SCH.SCHConstant`](../reference/sch/SCHConstant.md)) and utilities ([`DXP.Utils`](../reference/dxp/Utils.md), [`EDP.Utils`](../reference/edp/Utils.md)). |

The SDK assemblies target the .NET version that Altium Designer hosts: .NET 8 in Altium Designer 26.1, .NET 10 from
26.12 (see [Runtime and hosting](./runtime-and-hosting.mdx#the-net-runtime)). Many projects in the
[SDK examples](https://github.com/AltiumDeveloper/ad-sdk-examples) repository were written for earlier SDK versions
and target .NET Framework 4.x; their source code still shows the API usage, but use the target framework that matches
your SDK version. [Project setup](./project-setup.mdx) has a complete project file.

## The plugin factory and the server module

Altium Designer creates the extension through a plugin factory. The factory returns a `ServerModule` subclass, which
registers the extension's commands:

```csharp
using System.Runtime.InteropServices;
using DXP;

namespace MyExtension
{
    public interface IPluginFactory
    {
        object InvokePluginFactory(IClient client);
    }

    [ClassInterface(ClassInterfaceType.None)]
    public class PluginFactory : IPluginFactory
    {
        public object InvokePluginFactory(IClient client) => new PluginServerModule(client, "MyExtension");
    }

    [ClassInterface(ClassInterfaceType.AutoDispatch)]
    public class PluginServerModule : ServerModule
    {
        public PluginServerModule(IClient client, string moduleName) : base(client, moduleName) { }

        protected override void InitializeCommands()
        {
            ((CommandLauncher)CommandLauncher).RegisterCommand("HelloSchematic", Command_HelloSchematic, GetState_HelloSchematic);
        }

        protected override IServerDocument NewDocumentInstance(string kind, string fileName) => null;

        private void Command_HelloSchematic(IServerDocumentView view, ref string parameters)
        {
            // The command's work: see "Working with schematics".
        }

        private void GetState_HelloSchematic(IServerDocumentView context, ref string parameters, ref bool enabled,
            ref bool isChecked, ref bool visible, ref string caption, ref string imageFile)
        {
        }
    }
}
```

- `RegisterCommand` binds a command name to two methods: the command itself, and a *get state* method that Altium
  Designer calls to decide whether the command is enabled, checked or visible, and with which caption and image.
- `NewDocumentInstance` is used by extensions that implement a document editor; a command-only extension returns `null`.

## Installation files

Next to the assembly, an extension ships two text files with the extension's name:

- **`.ins`** declares the server (its name, the assembly file, version and description) and the commands it provides:

  ```text
  ClientInsFile 1.0

  Server
      EditorName        = 'MyExtension'
      EditorExePath     = 'MyExtension.DLL'
      EditorDescription = 'My first extension'
      Version           = 'Version 1.0.0.1'
  End

  Command Name='HelloSchematic' End
  ```

- **`.rcs`** defines the menus, toolbars and shortcuts that invoke the commands; see
  [Menus and the .rcs file](./menus.mdx).

The assembly and both files go into a folder under the Altium Designer `Extensions` folder,
`%ProgramData%\Altium\Altium Designer {<installation GUID>}\Extensions\<extension name>`.

## Registering the extension

Copying the files is not enough: Altium Designer loads only the extensions listed in `Extensions\ExtensionsRegistry.xml`.
An extension folder without an entry is ignored silently: its menus do not appear, its commands are not found by the
search, and none of its code runs. The project wizard of the Altium Developer extension adds the entry; an extension
that you build and copy yourself needs a deployment step that adds it, once, before Altium Designer starts:

```xml
<Item HRID="MyExtension" Guid="<a GUID of your own, the same for every installation>">
  <Path><full path of the extension folder></Path>
  <Status>0</Status>
  <VaultGuid></VaultGuid>
  <CreatedBy>Altium Limited</CreatedBy>
  <CategoryGuid>793A1F67-0B22-4E01-A5DE-3176A1E8C60D</CategoryGuid>
  <CategoryName></CategoryName>
  <ReadMe></ReadMe>
  <Help></Help>
  <Requirements></Requirements>
  <Title>MyExtension</Title>
  <ShortDescription></ShortDescription>
  <LongDescription></LongDescription>
  <SmallImage></SmallImage>
  <LargeImage></LargeImage>
  <Version></Version>
  <VersionGuid></VersionGuid>
  <ReleasedDate>0</ReleasedDate>
  <ReleaseNotes></ReleaseNotes>
  <DateInstalled>0</DateInstalled>
  <PlatformVersions>
    <DXP BuildNumber="1.0.6.0"/>
    <EDP BuildNumber="10.0.6.0"/>
    <MaxDXP BuildNumber="0.0.0.0"/>
    <MaxEDP BuildNumber="0.0.0.0"/>
  </PlatformVersions>
</Item>
```

This is the entry the Altium Developer wizard writes. `HRID` and `Title` are the extension's name, and `Path` is the
absolute path of its folder. Keep the rest of the file as it is: add the
`Item` element before the closing `</Extensions>` tag, and keep a backup. Altium Designer reads the file when it
starts.
